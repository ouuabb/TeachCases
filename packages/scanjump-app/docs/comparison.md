# 六种方案对比

## 总览表

| 方案 | 开发成本 | 稳定性 | 微信扫码 | 未安装处理 | 推荐场景 |
|------|---------|--------|---------|-----------|---------|
| URL Scheme | 低 | 中 | ❌ | 无响应 | 内部工具 |
| Universal Link | 中 | 最高 | ✅ | 打开网页 | 生产级首选 |
| H5 中转页 | 中 | 高 | ⚠️ 部分 | 下载引导 | 国内主流 |
| UniLink | 中 | 高 | ✅ | 打开网页 | uniCloud 生态 |
| 第三方服务 | 低 | 高 | ✅ | 下载引导 | 商业 App |
| Token 二维码 | 高 | 最高 | ✅ | 下载引导 | 企业级 |

## 详细对比

### 1. URL Scheme
- **原理**：自定义协议 `scanjump://page/detail?id=123`
- **优点**：实现最快、无需服务器
- **缺点**：未安装 App 时无响应、微信限制
- **适用**：企业内部工具、测试阶段

### 2. Universal Link / App Link
- **原理**：HTTPS 链接绑定 App
- **优点**：最完整方案、微信支持、未安装打开网页
- **缺点**：需要域名+HTTPS、配置复杂
- **适用**：正式商业 App 首选

### 3. H5 中转页 + Scheme
- **原理**：H5 页面检测环境后 Scheme 唤起
- **优点**：兼容性好、支持下载引导
- **缺点**：需要服务器、多一次跳转
- **适用**：国内 Android 应用

### 4. UniLink
- **原理**：DCloud 官方 Universal Link 封装
- **优点**：配置简单、官方支持
- **缺点**：依赖 uniCloud、灵活性低
- **适用**：uni-app + uniCloud 项目

### 5. 第三方 DeepLink 服务
- **原理**：中间层路由决策服务
- **优点**：数据统计、渠道分析、动态修改
- **缺点**：依赖第三方、有费用
- **适用**：商业 App、多渠道推广

### 6. Token 二维码
- **原理**：二维码只含 Token，服务端解析路由
- **优点**：安全性最高、支持过期/权限控制
- **缺点**：开发成本高、需要服务端
- **适用**：企业级安全场景

## 选择建议

```
你的场景是什么？
  ↓
企业内部工具 → URL Scheme（最简单）
  ↓
正式商业 App → Universal Link（最完整）
  ↓
国内 Android → H5 中转页（兼容性好）
  ↓
uniCloud 项目 → UniLink（官方支持）
  ↓
需要数据分析 → 第三方服务（统计能力强）
  ↓
安全要求高 → Token 二维码（最安全）
```

## 组合使用

生产环境建议组合使用：

```
二维码
  ↓
HTTPS 短链（Token 或自建）
  ↓
DeepLink 服务（判断设备、渠道）
  ↓
Universal Link / Scheme 唤起
  ↓
App 接收参数（DeepLinkManager）
  ↓
路由跳转
```

这就是微信、支付宝、企业 App 常见的架构。
